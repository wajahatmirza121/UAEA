Three cohesive files form the application root of the `app` package:
- `config.py` declares a single `Settings` class via `pydantic_settings.BaseSettings` with defaults for database URLs, Anthropic/OpenAI keys, CORS origins, rate limits, admin API key, environment, and log level; it loads `.env` automatically and exposes a module-level `settings` singleton consumed everywhere.
- `main.py` is the FastAPI app factory: it configures logging from `settings.log_level`, mounts a `slowapi.Limiter` keyed by remote IP, registers a custom `RateLimitExceeded` exception handler returning 429, adds `CORSMiddleware` based on `settings.cors_origins` (widening to `*` in development), mounts routers from `app.api.chat`, `app.api.lookup`, and `app.api.admin`, and exposes a `/health` endpoint. A per-session middleware stub is present for future session-scoped rate limiting on `/v1/chat/message`.
- `schemas.py` centralizes all Pydantic models used across endpoints, grouped into Lookup (ContactOut, CampusOut, DepartmentOut, FeeTariffOut, ServiceOut, DeadlineOut), Chat (ChatMessageRequest/Response, EscalateRequest/Response, SessionOut, ToolCallOut), Admin (FAQCreate/Out, FeeTariffCreate, AdminWriteResponse, UnansweredQueryOut, IntentCount), and RAG retrieval (ChunkResult). Output models use `ConfigDict(from_attributes=True)` to support direct ORM object serialization.
Dependency direction is one-way: `main.py` imports `config.settings` and the three router packages; `schemas.py` has no intra-app dependencies and is imported by the routers.
