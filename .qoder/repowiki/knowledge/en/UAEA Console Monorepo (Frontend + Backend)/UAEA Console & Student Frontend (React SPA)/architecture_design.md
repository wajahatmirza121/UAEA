Entry point `main.jsx` mounts `<App>` under `ReactDOM.createRoot`, which wraps the app in `AppProvider` (global store + role/theme) and `ToastProvider`, then configures `react-router-dom` routes split into two faces: root paths (`/`, `/chat`, `/services/*`, `/directory`) rendered inside `StudentShell`, and `/admin/*` pages rendered inside `AppShell`. Each shell owns chrome state (sidebar, command palette, mobile drawer) and renders page content via `<Outlet />`. Data access is centralized in `lib/api.js`, which exposes typed fetch wrappers over a FastAPI backend at `VITE_API_URL`; admin endpoints require an `X-API-Key` header. In-memory seed data from `mocks/` feeds `AppContext.store` so pages can render immediately; the context comments document a planned Phase-2 rewrite of `mutate()` to call the API instead of mutating local state, keeping all components agnostic of the data source. UI is organized as reusable primitives in `components/ui/`, feature-specific shells in `components/layout/` and `components/student/`, domain widgets in `components/content/`, `components/charts/`, and `components/data/`, while each `pages/<Feature>/index.jsx` composes those pieces into full screens. Styling uses layered CSS files under `styles/` (tokens, base, layout, components, per-surface variants) consumed via class names on the top-level `uaea` wrapper.
